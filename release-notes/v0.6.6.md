# SSH MountMate v0.6.6

Report Lustre project hard quota to the operating system through the bundled rclone mount.
Previously, MountMate could show free quota while the mounted drive still reported zero free
space from SFTP filesystem statistics, preventing the file manager from starting an upload.

- Prefer project hard block quota for Lustre mount capacity: total is the hard limit, and free
  space is the hard limit minus project usage, clamped to zero.
- Resolve symbolic links before looking up the Lustre project. Fall back to the existing SFTP
  `statvfs` / `df` behavior if Lustre tools or a usable project hard quota are unavailable.
- Bundle rclone v1.74.4 with a small SFTP capacity patch on all six platforms. Server quota
  enforcement and rclone's asynchronous cache write-back behavior are unchanged.

Finish uploads, unmount, update, and mount again so the new rclone process reports the corrected
capacity. Updating the interface alone does not replace an already running mount process.

---

通过随附的 rclone，把 Lustre 项目硬配额报告给操作系统。此前 MountMate 内可能显示仍有
可用配额，但挂载盘沿用 SFTP 文件系统统计、报告剩余空间为零，导致文件管理器无法开始上传。

- Lustre 挂载容量优先使用项目硬块配额：总容量为硬限额，剩余空间为硬限额减去项目已用量，最低为零。
- 查询前解析符号链接；没有 Lustre 工具或有效项目硬配额时，回退到原有 SFTP `statvfs` / `df`。
- 六个平台均随附带最小 SFTP 容量补丁的 rclone v1.74.4；服务器配额执行规则和异步缓存写回行为保持原样。

请先等待上传完成并卸载挂载盘，再更新、重新挂载，使新 rclone 进程报告修正后的容量。
仅更新界面不会替换仍在运行的挂载进程。
