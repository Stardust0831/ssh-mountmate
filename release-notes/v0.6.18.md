# SSH MountMate v0.6.18

- Fix native SFTP reporting `knownhosts: key mismatch` after **Trust and mount** when a server offers multiple host-key types. Mounts now negotiate a type already trusted for that host and port, while still verifying the actual public key. Both password and private-key login benefit, including trust saved by previous versions.
- Reduce connection delays: reuse trusted keys without a separate probe; first-use SSH discovery stops as soon as the public key arrives, with `ssh-keyscan` as a fallback. The bundled rclone immediately returns permanent host-key failures so the app can request confirmation of a changed key.
- Handle equivalent default-port trust records (`host` and `[host]:22`) consistently, and keep old mount-log errors from affecting a new attempt.
- Explain SFTP startup `unexpected EOF` errors more clearly. This release does not assume their server-specific cause is fixed; a working SSH shell alone does not establish that the SFTP subsystem works.

---

- 修复服务器提供多种主机公钥时，点击「信任并挂载」后仍出现 `knownhosts: key mismatch`：挂载会选择该主机和端口已信任的公钥类型，并继续校验实际公钥。密码、私钥登录均适用，旧版已保存的信任记录也能直接复用。
- 缩短连接等待：已有信任记录时不再额外探测；首次 SSH 探测收到公钥即结束，必要时回退到 `ssh-keyscan`。内置 rclone 遇到不可重试的主机身份错误会立即返回，让程序及时弹出指纹变化确认。
- 统一处理默认端口的等价记录（`host` 和 `[host]:22`），并避免旧挂载日志中的错误干扰本次连接的判断。
- 为 SFTP 启动阶段的 `unexpected EOF` 增加明确说明。这类错误的具体原因仍需按服务器排查；SSH 终端能登录并不代表 SFTP 子系统正常。
