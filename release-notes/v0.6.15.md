# SSH MountMate v0.6.15

- Fix Windows startup failures reporting missing `VCRUNTIME140.dll` by statically linking the MSVC runtime on x64 and ARM64. A separate Visual C++ Redistributable installation is no longer needed to launch the application.
- Inspect DLL imports in the final Windows executable and bundled rclone/Plink binaries during release checks, so preinstalled runtimes on CI machines cannot hide this packaging regression.
- Reduce the default VFS write-back delay from **5 seconds to 1 second**. On upgrade, the old 5s value becomes 1s; other values are preserved. Changes take effect on the next mount, and choosing 5s again after upgrading is respected. Upload concurrency remains 12.
- Clarify mount dependencies: Windows continues to use bundled WinFsp; macOS offers an experimental NFS backend using its built-in NFS client; Linux continues to use FUSE. The current NFS implementation cannot be used on Windows directly.

---

- 修复 Windows 双击启动时报缺少 `VCRUNTIME140.dll` 的问题：x64 和 ARM64 程序均静态链接 MSVC 运行库，启动应用无需另行安装 Visual C++ Redistributable。
- 发布时检查 Windows 最终程序及内置 rclone/Plink 的 DLL 依赖，避免构建机预装的运行库掩盖此类打包遗漏。
- 默认 VFS 写回延迟从 **5 秒缩短为 1 秒**。升级时原值 5s 迁移为 1s，其他值保留；下次挂载生效，升级后手动选回 5s 也会保留。上传并发仍为 12。
- 补充挂载依赖说明：Windows 继续使用内置 WinFsp；macOS 可选利用系统自带 NFS 客户端的实验性后端；Linux 继续使用 FUSE。当前 NFS 实现不能直接用于 Windows。
