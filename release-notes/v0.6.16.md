# SSH MountMate v0.6.16

- Native SFTP now asks you to confirm the server's SHA256 fingerprint on first connection. Confirming saves the displayed keys and continues mounting; cancelling leaves trust unchanged. Server fingerprints are separate from your login private key.
- When the server key changes, show the saved and received fingerprints for review. Confirmation updates only SSH MountMate's trust record, preserving your own SSH files and other servers' records. Multiple mappings of the same server share the confirmation.
- If `ssh-keyscan` fails, try a regular SSH handshake to retrieve the server key, working around the unsupported key-exchange bug in some Windows OpenSSH versions. This probe uses no login credentials, agent or user SSH config, and removes its temporary files afterward.
- If no public key can be obtained, explain the failure in a dialog with **Retry**, **Cancel** and **Copy details** instead of immediately ending with a generic `ssh-keyscan exited unsuccessfully` error.
- Headless/startup native SFTP mounts require an existing trusted key; confirm new or changed fingerprints in the GUI first. OpenSSH and interactive SSH connections retain their existing host-key policy.

---

- 原生 SFTP 首次连接时弹窗展示服务器 SHA256 指纹，确认后保存本次展示的公钥并继续挂载；取消不写入信任记录。服务器指纹与登录私钥是两回事。
- 服务器指纹变化时展示原指纹和本次指纹，供核实后确认。只更新 SSH MountMate 自己的信任记录，保留用户的 SSH 文件及其他服务器记录；同一服务器的多个挂载点共享确认结果。
- `ssh-keyscan` 失败时自动尝试普通 SSH 握手获取服务器公钥，兼容部分 Windows OpenSSH 版本的密钥交换问题。探测不使用登录凭据、密钥代理或用户 SSH 配置，完成后清理临时文件。
- 如果仍无法获得服务器公钥，弹窗解释原因并提供“重试、取消、复制详情”，不再直接以笼统的 `ssh-keyscan exited unsuccessfully` 错误结束。
- 原生 SFTP 的无界面／开机挂载需要已有受信任公钥，新指纹或变化的指纹请先在界面中确认。OpenSSH 和交互式 SSH 连接继续遵循原有的指纹验证策略。
